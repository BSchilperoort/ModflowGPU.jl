# Smoothed-aggregation AMG preconditioner (T4.3)

Measured 2026-11-08 on rocm (RX 7800 XT), same machine and software as the T4.1 baseline
(`benchmark/results/2026-11-07.md`), branch `T4.3-amg`:

```sh
julia -t 8 --project=benchmark benchmark/run.jl rocm indus continental global5m timed=0 precond=amg
julia -t 8 --project=benchmark benchmark/run.jl rocm global5m precision=double steps=1 maxsteady=0.01 precond=amg  # time split
```

Same models and IMS settings as the baseline (`synthetic_ims(:parity)`, CG, tight closures:
OUTER_DVCLOSE 1e-9, INNER_DVCLOSE 1e-10; Float32 floors in `:single`), steady state plus 30
daily steps. AMG defaults (`AMGOptions()`): strength `:offdiag`, θ = 0.08, Chebyshev degree
3 on the coarse levels and 1 on the finest level (fused), dense coarsest level ≤ 400 rows,
host setup with 8 Julia threads. The full CPU test suite ran at the same time as part of
the indus/continental runs, which may have slowed their host setup slightly.

| global5m | `:single` | (same) | 1.83 | 38 / 166 | 65.0 | 1.11 | +58 % |

- One host build per run. The first level aggregates exactly the vertical columns
  (3264793 ≈ half of the 6.6 M cells; vertical conductance ≈ 800 × horizontal). The
  operator complexity is 1.58.
- The aggregates are reused for all 31 steps. Prolongators and Galerkin products are
  recomputed on the device only for linear solves whose matrix changed (38 of 263 outer
  iterations on global5m). The other solves skip the update; their finest level still uses
  the current matrix.
- global5m steady, `:double`, timed run (5.28 s): `precond_setup` 2.6 s (host build 2.1 s
  plus 7 updates), `precond_apply` 1.66 s (16 ms per V-cycle before the fused finest
  level; about 12 ms after), SpMV + dot 0.20 s, assembly 0.19 s, period data 0.40 s.
- Device memory (peak vs the Jacobi peak, from the first table): global5m +51 % (`:double`)
  and +59 % (`:single`), continental +51 % and +58 %, indus +60 % and +67 %. The ≤ +60 %
  target is met on continental and global5m; indus `:single` (0.015 vs 0.009 GiB, a few
  MiB in absolute terms) exceeds it.

## Findings

- **Steady state.** AMG cuts the inner iterations by 80–90× and the steady-state time by
  4–8× compared with Jacobi. global5m `:double` takes 6.8 s, above the 5 s target. That
  time is about one third host build (2.2 s), one sixth device updates, and half V-cycles.
  T4.2's mc_ilu0 is faster on global5m (4.3 s), even though it needs 5× more iterations.
- **Daily steps.** Transient steps are slower with AMG than with Jacobi (global5m 0.99 vs
  0.62 s `:double`; indus 0.026 vs 0.006 s). With storage the matrix is strongly
  diagonally dominant, so Jacobi already needs few iterations (≈ 13 per outer iteration),
  and one V-cycle costs about 25 Jacobi iterations (global5m: ~12 ms vs 0.5 ms).
  Recommendation for T4.4: AMG (or mc_ilu0) for steady state and badly conditioned
  solves, and Jacobi or mc_ilu0 for transient steps (for example a per-solve choice).
- **Tried and rejected** (continental, steady inner iterations):
  - Diagonal-based strength measure: after the first outer iteration, cells whose boundary
    switched were left unaggregated (218 iterations in outer iteration 2). Replaced by the
    off-diagonal measure.
  - Frozen prolongators: 271 iterations, against 174 with device recomputation.
  - Power-iteration λmax: underestimates and makes the smoother unstable. Replaced by the
    Gershgorin bound.
  - Skipping updates when the matrix changes by < 1 %: 238 iterations, with spikes.
    Default: update on any change.
  - Degree-2 finest level: 141 iterations but slower than degree 1 with degree 3 on the
    coarse levels (142).
