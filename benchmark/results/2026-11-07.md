# Baseline benchmark (T4.1)

Measured 2026-11-07 with `benchmark/run.jl`, with nothing else running on the machine:

```sh
julia --project=benchmark benchmark/run.jl rocm indus continental global5m
JULIA_KA_CPU_THREADS=8 julia -t 8 --project=benchmark benchmark/run.jl cpu indus continental
JULIA_KA_CPU_THREADS=8 julia -t 8 --project=benchmark benchmark/run.jl cpu global5m timed=0 maxsteady=900
REFERENCE_DIR=reference julia --project=benchmark benchmark/run.jl mf6 indus continental global5m
```

## Models and settings

The synthetic coupling models of `benchmark/synthetic.jl` (docs/scaling.md): 2 confined
layers, CHD rim, RIV, DRN, EVT, RCH, STO. One steady-state day, then **30 daily transient
periods** (`ntransient = 30`; RCH and RIV stage change every period). IMS
`synthetic_ims(:parity)`: CG, OUTER_DVCLOSE 1e-9, INNER_DVCLOSE 1e-10, INNER_RCLOSE 1e-3
m³/d, 5000 inner / 500 outer, DBD under-relaxation (Float32 floors in `:single`:
dvclose ≥ 1e-6). No output files (`write_output = false`; mf6 without OC).

## What is measured

- **Wall time per step**: `ModflowGPU.update(sim)` + `synchronize` (period data, outer
  iterations, flows, budget), in a run without the section timer. `init`:
  `ModflowGPU.initialize` of the in-memory spec (connectivity, NPF, packages, device
  copies; not the spec build). mf6: per step from the time stamps of its `Solving: Stress
  period` lines on stdout; `init` = start to the first step (reading the input).
- **Iterations**: outer and inner per step (steady), mean per step over the 30 daily
  steps (`outer/step`, `inner/step`).
- **µs/inner**: steady wall time / inner iterations (includes the outer-iteration work).
- **SpMV GB/s**: `ModflowGPU.spmv!` alone on the assembled matrix (median of 30), T0.4
  *min* byte model `nja·(sizeof(T) + 4) + (n + 1)·4 + 2n·sizeof(Ts)`.
  **In-solver GB/s**: the `spmv_dot` sections of the timed run (CG's fused `q = A·p` and
  `p·q`, including the reduction's finalisation and the synchronisation), byte model
  `nja·(sizeof(T) + 4) + (n + 1)·4 + 4n·sizeof(Ts)` (p, column and row scale factors, q).
- **Peak device memory**: high-water mark of the HIP memory pool
  (`hipMemPoolAttrUsedMemHigh`, reset before `initialize`), so it includes every
  temporary of the run. Not measured on the CPU backend.
- **Time split**: a second run with `SyncTimer` installed (`ModflowGPU.set_section_timer!`),
  which synchronises at every section boundary and records a TimerOutputs tree;
  categories in `benchmark/run.jl`'s header. Without the timer each section costs one
  `Ref` load and a branch (src/instrument.jl).

## Findings

1. **The steady state dominates, and Jacobi-CG needs 20–36× the inner iterations of
   ILU0.** global5m `:double`: the steady step is 28.2 s of 46.7 s (8134 inner iterations
   in 13 outer); indus and continental need ~14,000 inner iterations in `:double` against
   394 / 450 for mf6's ILU0. Inner iterations per outer iteration do not grow with the
   grid in this synthetic model (indus 795, continental 777, global5m 626: the dense CHD
   rim and the drains keep it well conditioned), but the steady state of the real global
   model is expected to be harder (docs/scaling.md). This is what T4.2/T4.3 must cut.
2. **Large grids are bandwidth bound, and SpMV is already near the T4.5 target.** The
   in-solver fused SpMV + dot reaches 339 GB/s (`:double`, 73 % of the 466 GB/s triad) and
   306 GB/s (`:single`, 69 % of 445 GB/s) on global5m; SpMV alone 324 / 502 GB/s (the
   `:single` figure exceeds the triad: with Float32 values the matrix + vectors (≈ 210 MB)
   partly hit the 64 MB Infinity Cache between the back-to-back calls, and the *min* model
   counts x once). SpMV is ~50 % of the run, the update + reduction kernels ~30 %.
3. **Small grids are latency bound.** indus costs 72–77 µs per inner iteration on rocm in
   both precisions (≈ 36 µs per `spmv_dot` call for 33k rows: kernel launches and the two
   host synchronisations per CG iteration, not bandwidth), so the GPU is 3× slower than
   serial mf6 in the indus steady state (1.10 s vs 0.35 s) despite ~equal outer counts.
   The daily steps are already 16× (`:double`) / 32× (`:single`) faster than mf6 on indus,
   because they need few inner iterations.
4. **The daily step of global5m already takes < 1 s**: 0.62 s (`:double`) and 0.23 s
   (`:single`) with tight closures, of which ~60 % is the linear solve (110 / 39 inner
   iterations per step, 8.3 / 5.1 outer iterations: OUTER_DVCLOSE 1e-9 makes the transient
   steps iterate), ~20 % assembly (14 ms per outer iteration on 6.6 M nodes, i.e. far from
   bandwidth bound: ≈ 1 GB moved would take 2–3 ms) and ~10–27 % period data.
5. **Host transfers: the period data.** Each new stress period rebuilds and uploads the
   RCH and RIV records on the host (`apply_period!`: the multiplier, offsets, copies):
   64 ms per period on global5m in both precisions, 14 % of the `:single` run. In
   ModflowCoupling, every daily step sets RCH/RIV/DRN values through the stepping API,
   which takes the same path (`set_bound!`), so this cost will be paid every day.
   Reduction results are read from host-mapped memory (no copies), and `mirrors` and
   `output` are absent in these runs.
6. **mf6 vs ModflowGPU.** continental: mf6 102.5 s for the 31 steps vs 8.6 s (`:double`)
   / 3.0 s (`:single`) on rocm (12× / 34×), and 56.8 s / 19.2 s on the CPU backend.
   MF6_GLOBAL5M_FINDING
7. **Device memory.** The pool high-water mark equals the device arrays of T3.4 (3.019 GiB
   `:double`, 1.904 GiB `:single` on global5m): no temporaries during the run.
8. **Instrumentation cost.** AB_RESULT With the timer installed, synchronising at every
   section boundary costs +19–28 % on indus (rocm), where kernels are short, and nothing
   measurable on the large grids. The timed runs of global5m on rocm (−3 %, −11 %) and of
   the CPU backend on indus (−16 %, −43 %) were *faster* than the untimed runs (the rocm
   untimed numbers reproduce within 1–3 %): extra synchronisation between kernels helps
   in those cases. Not understood yet (candidates: the HIP queue or power state with long
   runs of asynchronous launches on rocm; POCL's scheduling on the CPU); an open item for
   T4.5, which changes the launch pattern anyway. The splits are therefore indicative to
   about ±10 %.

The card's example targets ("a daily step of global5m in < 1 s and steady state in
minutes") are already met by the baseline (0.62 s; 28 s), so the targets above are
tighter. They are for the synthetic model; the real global model may need more
iterations in the steady state.
