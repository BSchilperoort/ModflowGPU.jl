# T4.2: Chebyshev and multicolour smoothers

Measured 2026-11-08 with `benchmark/run.jl` (machine, models and settings as in the T4.1
baseline, `benchmark/results/2026-11-07.md`: synthetic coupling models, steady state +
30 daily steps, IMS `synthetic_ims(:parity)` with CG, tight closures). Every GPU run held
the `gpu-bench` lock; the final rocm table was measured with nothing else using the GPU.

```sh
julia --project=benchmark benchmark/run.jl rocm indus continental global5m precision=double timed=0 precond=jacobi,mc_ilu0
julia --project=benchmark benchmark/run.jl rocm indus continental global5m precision=double timed=0 precond=jacobi,chebyshev,mc_sgs,mc_ilu0
JULIA_KA_CPU_THREADS=8 julia -t 8 --project=benchmark benchmark/run.jl cpu indus continental precision=double timed=0 precond=jacobi,chebyshev,mc_sgs,mc_ilu0
# and the same with precision=single
```

Preconditioners (`preconditioner` keyword of `ModflowGPU.run` / `initialize`;
src/solver/precond/, docs/mf6_notes.md):

- `jacobi`: the T2.7 baseline (fused into the CG kernels).
- `chebyshev`: Jacobi-preconditioned Chebyshev polynomial, degree 4 on `[λmax/30, λmax]`,
  `λmax` from 10 Lanczos (Jacobi-PCG) steps × 1.1, capped by Gershgorin.
- `mc_sgs`: symmetric Gauss–Seidel in red–black order (`(i + j + k)` parity).
- `mc_ilu0`: ILU(0) in red–black order, factorised on the device in every outer iteration
  (one pass per colour); applied in 2 kernels.

## Findings

1. **MC-ILU0 is the fastest in every case** (both backends, both presets, all sizes):
   12–15× fewer inner iterations than Jacobi, steady state 5–9× faster. It meets the
   Phase 4 targets for the global5m steady state (< 5 s `:double`: 4.31 s) and the indus
   steady state (< 0.35 s: 0.13 s), and its inner counts are within 3× of mf6's
   natural-order ILU0 (indus 1055 vs 394, continental 1148 vs 450, global5m 561 vs 218)
   and roughly independent of size per outer iteration (55–64 `:double`).
2. Chebyshev (degree 4) cuts iterations 4× but each costs 3 SpMVs and its Lanczos setup
   runs every outer iteration: faster than Jacobi in the steady state, slower in the
   daily steps. MC-SGS halves the iterations of Jacobi, about break-even in time.
3. Cost per inner iteration of MC-ILU0 is 2.3× Jacobi's on global5m (≈ 7.7 ms vs 3.4 ms
   per inner iteration in `:double`, including outer work): the colour-ordered apply
   (386 µs on continental vs 295 µs for SpMV + dot) has stride-2 vector access, and the
   non-fused CG loop has one more reduction. Candidates for T4.5: vectors in colour
   order, fusing `r·z` into the update.
4. **Daily steps gain little** (global5m 0.61 → 0.50 s `:double`): with ~3 inner
   iterations per outer iteration, the per-outer costs dominate (assembly 14 ms,
   preconditioner setup ≈ 13 ms on global5m, period data). The setup could be skipped for
   confined models when only the diagonal changes slightly (open).
5. Memory: MC-ILU0 adds a colour-ordered copy of the matrix (`nja·(Tp + 8)` bytes + 4
   index vectors): +0.73 GiB (+24 %) on global5m `:double`, +0.56 GiB `:single`.
6. MILU relaxation does not help in red–black order (indus `:double`: 1055 inner at 0,
   1274 at 0.97, 1845 at 0.99), so `relax = 0`.
7. The 5.8 s global5m steady time seen once during development came from a profiling
   run while other agents used the GPU; the locked re-run gives 4.31 s (4.42 s earlier).
