Output files

ModflowGPU writes the head file (.hds), the budget file (.cbc, with DATA-SPDIS when NPF has SAVE_SPECIFIC_DISCHARGE and DATA-SAT when it has SAVE_SATURATION), the binary grid file (.dis.grb, .disv.grb, .disu.grb, unless NOGRB), the model listing file (.lst), the observation files (OBS6) and the CSV files (BUDGETCSV, CSV_OUTER_OUTPUT, CSV_INNER_OUTPUT, AUTO_FLOW_REDUCE_CSV) in MF6's formats (see Differences from MODFLOW 6). The readers on this page read these files from ModflowGPU and from MF6 alike, so they can also be used to compare the two. The binary files can be read by FloPy as well.

Head and budget files are indexed when opened (the record headers only); the data of a record is read when asked for.

using ModflowGPU
hf = open_head_file("path/to/simulation/model.hds")
h = read_head(hf, length(hf))            # the last saved heads, (ncol, nrow, nlay)

bf = open_budget_file("path/to/simulation/model.cbc")
wel = read_budget(bf; text = "WEL")      # one BudgetList per time step
ModflowGPU.open_head_file — Function
open_head_file(path; grid = :auto) -> HeadFile

Index the head file at path: read every record header (not the data) and group the layer records of each saved array. grid sets the shape of the arrays returned by read_head: :dis gives (ncol, nrow, nlay), :disv (ncpl, nlay), :disu a vector of nodes, and :auto the record layout (m1, m2, nlay) (which is the DIS shape). All values are Float64, in MF6's user-node order.

Reads head files of ModflowGPU and of MF6 alike. Throws an ModflowGPU.MF6BinaryFileError for a malformed file.

Example

hf = open_head_file("path/to/simulation/model.hds")
ModflowGPU.head_times(hf)        # the times of the saved arrays
h = read_head(hf, length(hf))    # the last one, (ncol, nrow, nlay) for DIS
h = read_head(hf; kper = 2, kstp = 1)
source
ModflowGPU.HeadFile — Type
HeadFile

Index of an MF6 head file, built by open_head_file: the path, the grid layout used to shape arrays (:dis, :disv, :disu or :auto) and the saved arrays (steps, one ModflowGPU.HeadStep each, in file order). Data are read lazily by read_head. length(hf) is the number of saved arrays.

source
ModflowGPU.HeadStep — Type
ModflowGPU.HeadStep

One saved array of a head file (all its layer records), an element of HeadFile.steps: kstp, kper (time step and stress period), pertim, totim (time in the period and in the simulation), text (16 characters as in the file, e.g. "HEAD "), m1, m2 (per-layer record size), nlay (number of layer records) and the byte offsets of the data of each layer record.

source
ModflowGPU.read_head — Function
read_head(hf, i) -> Array{Float64}
read_head(hf; kstp, kper, totim, text) -> Array{Float64}

Read the i-th saved array of the head file (or the one selected by find_head_step), shaped as set by the grid of open_head_file. Heads are in the model's length units; cells outside the model hold ModflowGPU.HNOFLO, dry cells ModflowGPU.HDRY. See open_head_file for an example.

source

Index of the saved array matching all given keys (text is compared without the padding blanks and case-insensitively). Throws an ArgumentError if there is no match or more than one.

Example

i = ModflowGPU.find_head_step(hf; kper = 1, kstp = 10)
read_head(hf, i)

(kstp, kper) of each saved array of the head file, in file order.

ModflowGPU.head_times(hf) -> Vector{Float64}

Simulation time (totim) of each saved array of the head file, in file order.

ModflowGPU.open_budget_file — Function
open_budget_file(path) -> BudgetFile

Index the budget file (.cbc) at path: read the header of every record (not the data). Only compact records with IMETH 1 or 6, the ones MF6 writes, are supported. Reads budget files of ModflowGPU and of MF6 alike. Throws an ModflowGPU.MF6BinaryFileError for a malformed file.

Example

bf = open_budget_file("path/to/simulation/model.cbc")
ModflowGPU.budget_texts(bf)     # e.g. ["FLOW-JA-FACE", "DATA-SPDIS", "WEL", "RIV", ...]
ModflowGPU.budget_kstpkper(bf)  # [(1, 1), (1, 2), ...]
riv = read_budget(bf; text = "RIV", kper = 2, kstp = 1)   # one BudgetList
sum(only(riv).q)        # net river flow into the model (L³/T)
source
ModflowGPU.BudgetFile — Type
BudgetFile

Index of a budget file, built by open_budget_file: the path and the header of every record (records, ModflowGPU.BudgetRecords in file order). Data are read lazily by read_budget. length(bf) is the number of records.

source
ModflowGPU.BudgetRecord — Type
ModflowGPU.BudgetRecord

Header of one record of a budget file, an element of BudgetFile.records, as indexed by open_budget_file:

  • kstp, kper, text (16 characters as in the file, e.g. " FLOW-JA-FACE"), ndim1, ndim2, ndim3 (the grid dimensions; ndim3 as written, i.e. negative for MF6's compact header), imeth, delt, pertim, totim;
  • for IMETH 6: modelnam1, paknam1, modelnam2, paknam2 (16 characters each), auxtxt (auxiliary names, 16 characters each); empty strings for IMETH 1;
  • n: number of values (IMETH 1) or list entries (IMETH 6), and offset, the byte offset of the data.
source
ModflowGPU.BudgetList — Type
BudgetList

The entries of an IMETH 6 budget record, as returned by read_budget: id1, id2 (Int32 node numbers; for a stress package id1 is the model cell (user node) and id2 the package entry), q (flow, L³/T, positive into the model cell id1), and aux (naux × nlist matrix of auxiliary values, in the order of the record's auxtxt). length(list) is the number of entries.

source
ModflowGPU.read_budget — Function
read_budget(bf, i) -> Vector{Float64} or BudgetList
read_budget(bf; text, kstp, kper, ...) -> Vector

Read the data of record i: a vector of n values for IMETH 1 (user-node order, reshape(v, ndim1, ndim2, -ndim3) gives the grid shape; FLOW-JA-FACE is a vector of length NJA), a BudgetList for IMETH 6. The keyword form reads all records matching find_budget_records, in file order. Flows are in L³/T in the model's units. See open_budget_file for an example.

source
ModflowGPU.find_budget_records — Function
ModflowGPU.find_budget_records(bf; text, kstp, kper, totim, imeth, paknam2, modelnam2) -> Vector{Int}

Indices of the records matching all given keys. Texts and names are compared without padding and case-insensitively. Note that GWF-GWF exchange flows are IMETH 6 records with text FLOW-JA-FACE (and the exchange name as paknam2); use imeth = 1 for the model's own FLOW-JA-FACE array.

Example

idx = ModflowGPU.find_budget_records(bf; text = "STO-SS")
[bf.records[i].totim for i in idx]
source

ModflowGPU.read_grb — Function
read_grb(path) -> BinaryGridFile

Read an MF6 binary grid file (.dis.grb, .disv.grb, .disu.grb), written by ModflowGPU or MF6 for the DIS, DISV or DISU package. It holds the grid and the model's connectivity (IA, JA), which give the meaning of the FLOW-JA-FACE budget record. Throws an ModflowGPU.MF6BinaryFileError for a malformed file.

Example

g = read_grb("path/to/simulation/model.dis.grb")
g.grid                  # "DIS"
g["NCOL"], g["NROW"], g["NLAY"]
ia, ja = g["IA"], g["JA"]
source
ModflowGPU.BinaryGridFile — Type
BinaryGridFile

Contents of an MF6 binary grid file (see read_grb): grid ("DIS", "DISV" or "DISU"), version, the four raw header lines, lentxt, the variables in file order and their data by name (INTEGER as Int32, DOUBLE as Float64; scalars as numbers, NDIM 1 variables as vectors, NDIM 2 as matrices with the dimensions in the file's (Fortran) order). g[name] and haskey(g, name) access data.

source
ModflowGPU.GrbVariable — Type
ModflowGPU.GrbVariable

One variable of a binary grid file, an element of BinaryGridFile.variables: name (e.g. "IA"), type (:INTEGER or :DOUBLE), dims (empty for a scalar) and definition, the definition line as written in the file (LENTXT characters, including the trailing newline).

source
ModflowGPU.read_listing_budgets — Function
read_listing_budgets(path) -> Vector{ListingBudget}

All budget tables (... BUDGET FOR ... AT END OF TIME STEP ...) of a model listing file (.lst) of ModflowGPU or MF6, in file order, with the values as printed (rates L³/T, volumes L³). Throws an ModflowGPU.MF6InputError for a table it cannot read.

Example

tables = read_listing_budgets("path/to/simulation/model.lst")
last(tables).rate_percent_discrepancy
[(t.name, t.rate_in, t.rate_out) for t in last(tables).terms]
source
ModflowGPU.ListingBudget — Type
ListingBudget

One budget table of a listing file: title (e.g. "VOLUME"), zone (e.g. "ENTIRE MODEL"), kstp, kper (0 if the printed number overflowed its field), the terms (ModflowGPU.ListingBudgetTerm), the totals total_cum_in, total_cum_out, total_rate_in, total_rate_out, the differences cum_in_minus_out, rate_in_minus_out and the printed cum_percent_discrepancy, rate_percent_discrepancy.

source
ModflowGPU.ListingBudgetTerm — Type
ModflowGPU.ListingBudgetTerm

One term of a listing-file budget table, an element of ListingBudget.terms: name (budget text, e.g. "WEL", "STO-SS"), package (package name column, "" when the table is unlabeled), cumulative volumes cum_in, cum_out and rates rate_in, rate_out (both non-negative, as printed).

source
ModflowGPU.listing_rates — Function
ModflowGPU.listing_rates(path, term; title = "VOLUME", zone = "ENTIRE MODEL")
    -> Vector{Tuple{Float64, Float64}}

(rate in, rate out) of the budget term term in every budget table of the listing file with the given title and zone (by default the model's volume budget; e.g. one table per stress period with PRINT BUDGET LAST), summed over the rows whose name or package name equals term (case-insensitive). Ported from the listing_rates helper of ModflowCoupling's tests, which took the first matching row; summing gives the same for a single package and the model total for several packages of one type. Rates are in L³/T in the model's units.

Example

ModflowGPU.listing_rates("path/to/simulation/model.lst", "RIV")   # [(in, out) per table]
source
ModflowGPU.percent_discrepancy — Function
ModflowGPU.percent_discrepancy(total_in, total_out) -> Float64
ModflowGPU.percent_discrepancy(b::ModelBudget) -> Float64

MF6's percent discrepancy 100 (in - out) / ((in + out) / 2), zero when both are zero (budget_ot in Budget.f90). For a ModelBudget: of its total rates in and out (see cum_percent_discrepancy for the cumulative volumes).

Example

julia> ModflowGPU.percent_discrepancy(101.0, 99.0)
2.0

julia> ModflowGPU.percent_discrepancy(0.0, 0.0)
0.0
source

ModflowGPU.MF6BinaryFileError(path, offset, msg)

Error raised by the output readers (open_head_file, open_budget_file, read_grb) when an MF6 binary output file is malformed or truncated: offset is the byte offset in the file where the problem was found.

Observation files

The observation output of OBS6 input (CSV or BINARY), of ModflowGPU and of MF6; the paths of a run are in RunResult.obs_files.

obs = read_observations("path/to/simulation/model.obs.head.csv")
obs.names, obs.times, obs.values   # values: one row per time step, one column per observation
ModflowGPU.read_observations — Function
read_observations(path) -> ObservationFile

Read an observation output file of ModflowGPU or MF6 (OBS6 CONTINUOUS FILEOUT): the CSV file (a time column, then one column per observation) or the BINARY file (MF6's cont double or cont single format).

Example

result = run_simulation("path/to/simulation"; outdir = "out")
obs = read_observations(result.obs_files[1])
obs.names, obs.times, obs.values[:, 1]
source
ModflowGPU.ObservationFile — Type
ObservationFile

An observation output file read by read_observations: path, the observation names (upper case, the column order), the times (end of each time step) and values, a matrix with one row per time and one column per observation (Float64; MF6 writes 3.0e30 for a package observation that matches no boundary in a step).

source
ModflowGPU.OBSNODATA — Constant
OBSNODATA

The value MF6 writes for a package observation that matches no boundary in the time step (DNODATA, 3.0e30), e.g. a cell without a record of the package, or TO-MVR without a mover.

source

CSV output files

The CSV files of OC BUDGETCSV, IMS CSV_OUTER_OUTPUT and CSV_INNER_OUTPUT and WEL AUTO_FLOW_REDUCE_CSV are written as MF6 writes them (columns on Supported packages); the paths of a run are in RunResult.csv_files. They are plain CSV with a header line, readable with any CSV reader, e.g. with DelimitedFiles:

using DelimitedFiles
result = run_simulation("path/to/simulation")
data, header = readdlm(result.csv_files[1], ','; header = true)
