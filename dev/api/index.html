API reference

The public API of ModflowGPU, one page per area:

  • Running a simulation: run_simulation and its result, loading MF6 input, errors.
  • Backends and precision: choosing the CPU or a GPU, and the precision presets.
  • Stepping API: running a simulation one time step at a time and reading or setting its variables, for coupling.
  • Building models: a simulation from Julia arrays, written as MF6 input.
  • Output files: reading head, budget, binary grid and listing files.
  • For backend authors: the hooks a GPU package extension implements.

Names written as ModflowGPU.name on these pages are public but not exported: write them qualified. All others are exported by using ModflowGPU. The exported names are the entry points: running, backends and precision, the stepping calls, the builder functions and the output readers with their result types. Small helpers, such as ModflowGPU.oc_record, the step and record lookups of the readers (ModflowGPU.find_budget_records, ModflowGPU.head_times, ...) and ModflowGPU.percent_discrepancy, are public but not exported.

ModflowGPU.run and ModflowGPU.finalize, the names used before version 0.1 exported anything, are the same functions as run_simulation and finalize_simulation and keep working. They are not exported because they would clash with Base.run and Base.finalize.

The BMI functions are methods of BasicModelInterface's own functions for Simulation (the BMI specification) and MF6Model (libmf6's BMI, as ModflowInterface.jl) and are called qualified, for example BasicModelInterface.update(sim); see BMI.

ModflowGPU.ModflowGPU — Module
ModflowGPU

The groundwater-flow (GWF) model of MODFLOW 6 on GPUs and CPUs, written with KernelAbstractions. It reads MF6 input files, writes MF6 head, budget and listing files, and can be run one time step at a time for coupling.

Load the package of your GPU next to it to enable that backend (using AMDGPU, ModflowGPU; also CUDA, oneAPI, Metal, OpenCL). The exported names cover:

  • running a simulation: run_simulation, load_simulation;
  • backends and precision: select_backend, resolve_precision;
  • the stepping API: initialize, do_time_step, finalize_simulation, get_value, set_value, ...;
  • building models in Julia: build_dis, ..., build_simulation, write_simulation;
  • reading output files: open_head_file, open_budget_file, read_grb, read_listing_budgets.

Other documented names are public but not exported, because their names are generic (ModflowGPU.run, ModflowGPU.finalize, ModflowGPU.solve, ModflowGPU.update), they are small helpers (ModflowGPU.oc_record, ModflowGPU.head_times, ModflowGPU.find_budget_records, ModflowGPU.percent_discrepancy, ...) or they are for backend authors (ModflowGPU.register_backend!). BMI is implemented as methods of BasicModelInterface's functions (BasicModelInterface.update(sim)), for Simulation (the BMI specification) and for MF6Model (libmf6's BMI, as ModflowInterface.jl).

Example

using ModflowGPU
result = run_simulation("path/to/simulation"; backend = select_backend("auto"))
result.converged
