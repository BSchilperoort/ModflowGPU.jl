Backends and precision

A backend is the device a simulation runs on, as a KernelAbstractions Backend. GPU backends become available when their package is loaded next to ModflowGPU (for example using AMDGPU, ModflowGPU); select_backend picks one by name. The precision preset sets the floating-point types of the model state, the linear solver and the preconditioner; resolve_precision shows what a preset means on a backend.

julia> backend = select_backend("cpu");

julia> resolve_precision(backend, :auto)
(T = Float64, Ts = Float64, Tp = Float32)
ModflowGPU.select_backend — Function
select_backend(name="auto")

Select the KernelAbstractions backend to run the model on. This is evaluated at runtime (not during precompilation), so the same precompiled package can be used on machines with and without a GPU.

name is one of "auto", "cpu", "cuda", "rocm", "metal", "oneapi", "opencl". GPU backends are only available once their package is loaded (e.g. using AMDGPU). With "auto" the first loaded and functional GPU backend is used, falling back to CPU. Explicitly requesting a GPU backend that is not loaded or not functional throws an error.

A KernelAbstractions.Backend can also be passed directly, which is returned as is.

Returns a KernelAbstractions.Backend, to pass as the backend keyword of run_simulation and initialize. The CPU backend of KernelAbstractions 0.10 is POCLBackend (CPU()); it is meant for tests and small models.

Example

julia> backend = select_backend("cpu");

julia> backend_name(backend)
"POCLBackend"

With a GPU package loaded:

using AMDGPU, ModflowGPU
backend = select_backend("auto")   # ROCBackend() when the GPU works, else the CPU

ModflowGPU.backend_options — Function
backend_options() -> Vector{String}

All valid backend names for select_backend: "auto", "cpu" and the GPU backends, known ones in order of preference for "auto" first. A GPU backend is listed even when its package is not loaded; selecting it then throws an error that names the package to load.

Example

julia> backend_options()
7-element Vector{String}:
 "auto"
 "cpu"
 "cuda"
 "rocm"
 "metal"
 "oneapi"
 "opencl"

ModflowGPU.backend_name — Function
backend_name(backend) -> String

The name of the type of the KernelAbstractions backend, e.g. "POCLBackend" (KA's CPU()), "ROCBackend" (AMDGPU) or "CUDABackend". Used in log messages and the listing file.

Example

julia> backend_name(select_backend("cpu"))
"POCLBackend"

ModflowGPU.supports_float64 — Function
supports_float64(backend)::Bool

Whether backend can run kernels in Float64, which the :double and :mixed precision presets need. Extension hook like ModflowGPU.pin_memory!: the default is true (CPU, CUDA, ROCm). The Metal extension returns false, and the oneAPI and OpenCL extensions query the device.

This is deliberately not KernelAbstractions.supports_float64, whose default (through KernelInterface, since KernelAbstractions 0.10) is false for backends that do not define it.

Example

julia> supports_float64(select_backend("cpu"))
true
source
ModflowGPU.resolve_precision — Function
resolve_precision(backend, preset = :auto) -> (; T, Ts, Tp)

Resolve a precision preset to the floating-point types for state and assembly (T), the Krylov solver (Ts) and the preconditioner (Tp):

PresetTTsTp
:doubleFloat64Float64Float64
:mixedFloat64Float64Float32
:singleFloat32Float32Float32
:auto:mixed if supports_float64(backend), else :single

:mixed keeps the state, assembly and Krylov vectors in Float64 (the :double parity tolerances hold) and stores every preconditioner's data (Jacobi minv, Chebyshev and multicolour operator copies and factors, the AMG hierarchy) in Float32. It is the :auto default on backends with Float64 because it is as accurate as :double and 10–20 % faster with less memory (measured in docs/dev/precision.md).

The result is a NamedTuple, so T, Ts, Tp = resolve_precision(backend, preset) works. Requesting :double or :mixed on a backend without Float64 support throws an error. preset may also be a string ("single").

Example

julia> backend = select_backend("cpu");

julia> resolve_precision(backend)
(T = Float64, Ts = Float64, Tp = Float32)

julia> resolve_precision(backend, :single)
(T = Float32, Ts = Float32, Tp = Float32)
