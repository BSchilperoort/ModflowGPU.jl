Running a simulation

Run an MF6 simulation directory from start to end with run_simulation. It returns a RunResult with the final heads and the budget of every time step, and writes the output files that the OC package of the input asks for. MF6 input is read by load_simulation, which run_simulation calls for you; call it yourself to inspect or change a simulation before running it.

using ModflowGPU
result = run_simulation("path/to/simulation"; backend = select_backend("auto"))
result.converged
ModflowGPU.percent_discrepancy(result.budgets[end])
ModflowGPU.run_simulation — Function
run_simulation(simdir::AbstractString; kwargs...) -> RunResult
run_simulation(spec::SimulationSpec; kwargs...) -> RunResult

Run the MF6 simulation in directory simdir (the directory with mfsim.nam), or a loaded or built SimulationSpec, from start to end. The simulation has one IMS solution with one GWF model, or several connected by GWF6-GWF6 exchanges (T6.6; solved as one system, as MF6 does). Each time step applies the stress-period data, solves the heads with the outer (Picard) iterations, computes flows and the budget, and writes the output that the OC package of each model asks for: the head file, the budget file and the model listing file (budget tables), under the names given in the input.

Keywords:

  • backend = CPU(): the KernelAbstractions backend, e.g. from select_backend;
  • precision = :auto: a precision preset, see resolve_precision (:auto is :mixed on backends with Float64, else :single);
  • outdir = simdir: the directory for the output files (spec.simdir for a spec); a directory inside the one named by the environment variable REFERENCE_DIR (the MF6 reference runs of the parity tests) is an ArgumentError;
  • write_output = true: false writes no head, budget, grid or listing files (T6.9: the OBS6 observation files are written in every run, as MF6 does; T6.17: so are the CSV files);
  • closures = nothing: a NamedTuple that overrides IMS settings, with any of outer_dvclose, outer_maximum, inner_dvclose, inner_rclose, inner_maximum (closures in the model's units); in :single, closures below what Float32 can reach are raised (logged);
  • preconditioner = :auto: the linear-solver preconditioner, replacing the ILU0, MILU0 or ILUT of IMS (a ModflowGPU option, not in MF6 input): :auto (:mc_ilu0), :jacobi, :chebyshev, :mc_sgs, :mc_ilu0 or :amg;
  • precond_options = (;): keywords for the preconditioner: degree for :chebyshev, relax for :mc_sgs and :mc_ilu0, the AMG options for :amg (developer notes, docs/dev/mf6_notes.md).

Returns a RunResult with the heads, the budgets and the iteration counts. A time step that does not converge throws a ConvergenceError after writing its output, unless the simulation has the CONTINUE option. Invalid or unsupported input throws an ModflowGPU.MF6InputError or an MF6UnsupportedError before anything runs.

ModflowGPU.run is the same function under its earlier name.

Example

using ModflowGPU
backend = select_backend("auto")
result = run_simulation("path/to/simulation"; backend)
result.converged

# on a GPU without Float64, or to save memory:
result = run_simulation("path/to/simulation"; backend, precision = :single)

ModflowGPU.run — Function
ModflowGPU.run(simdir; kwargs...) -> RunResult

The same function as run_simulation, under the name used before it was exported. Not exported, because it would clash with Base.run; it is kept (not deprecated) for code that calls ModflowGPU.run.

source
ModflowGPU.RunResult — Type
RunResult

What run_simulation returns. Fields:

  • converged::Bool: every time step converged;
  • heads::Vector{Float64}: the absolute heads at the end of the run, per model node (cells with IDOMAIN > 0, in MF6's reduced node order), in the model's length units; with several models (T6.6) the nodes of every model, one model after the other in the order of the solution (models[k].nodes gives each model's range);
  • steps::Vector{StepResult}: per time step its StepResult (time, iterations);
  • budgets::Vector{ModelBudget}: per time step the volumetric budget (ModelBudget); with several models one per model and time step (in the order of models; ModelBudget.model is the model's name);
  • head_file, budget_file, listing_file: the paths of the output files ("" when not written); with several models those of the first model;
  • obs_files: the paths of the observation output files (OBS6 CONTINUOUS FILEOUT; the model's, then the stress packages'), empty without observations or output; read them with read_observations; with several models those of every model, then those of the GWF-GWF exchanges;
  • csv_files: the paths of the CSV files (T6.17: IMS CSV_OUTER_OUTPUT and CSV_INNER_OUTPUT, OC BUDGETCSV, WEL AUTO_FLOW_REDUCE_CSV; written in every run, as MF6 does), empty when the input asks for none;
  • models: per model (T6.6; one entry for a single model) a NamedTuple with name, nodes (its range in heads), head_file, budget_file, listing_file, obs_files and grb_file (T6.9: the binary grid file, "" with NOGRB or without output);
  • T, Ts, Tp: the precision types used (see resolve_precision);
  • model: the model, still on the device (internal; with several models the merged model of the solution; its memory is released by the garbage collector).

Example

result = run_simulation("path/to/simulation")
result.converged
result.budgets[end].terms   # budget terms of the last time step

# several models (e.g. a parent and a child grid connected by a GWF-GWF exchange):
[(m.name, m.head_file) for m in result.models]
child = result.models[2]
result.heads[child.nodes]                                 # its final heads
filter(b -> b.model == child.name, result.budgets)        # its budgets
source
ModflowGPU.ModelBudget — Type
ModelBudget

The volumetric budget of a model for one time step, as in MF6's listing file: kstp and kper (time step and stress period numbers), the terms (BudgetTerm) in MF6's order (STO-SS, STO-SY when ICONVERT is used, then the stress packages; in a multi-model solution then the GWF-GWF exchange terms FLOW-JA-FACE and FLOW-JA-FACE-CHD, package name the exchange's, e.g. GWF-GWF_1) and model, the model's name. Computed on the device in every time step, also when no budget is printed or saved; found in RunResult.budgets and Simulation.budgets (one per model and time step).

percent_discrepancy(b) and cum_percent_discrepancy(b) give MF6's percent discrepancy of the rates and of the cumulative volumes.

Example

b = run_simulation("path/to/simulation").budgets[end]
[(t.name, t.rate_in, t.rate_out) for t in b.terms]
ModflowGPU.percent_discrepancy(b)
source
ModflowGPU.BudgetTerm — Type
BudgetTerm

One row of a ModelBudget. Fields:

  • name: the budget text, e.g. "STO-SS", "CHD", "RCHA";
  • package: the package name as in the listing file, e.g. "STORAGE", "CHD_0";
  • rate_in, rate_out: the inflow and outflow rates of the time step (non-negative, Float64, volume per time, L³/T in the model's units);
  • cum_in, cum_out: the cumulative inflow and outflow volumes since the start (L³).
source

ModflowGPU.ConvergenceError — Type
ConvergenceError(kper, kstp, iterations)

Thrown by run_simulation (and BasicModelInterface.update) when time step kstp of stress period kper did not converge within OUTER_MAXIMUM (iterations outer iterations) and the simulation has no CONTINUE option. As MF6, the run stops after writing the output of that step.

Example

try
    run_simulation("path/to/simulation")
catch e
    e isa ConvergenceError || rethrow()
    @warn "stopped in stress period $(e.kper), time step $(e.kstp)"
end

ModflowGPU.load_simulation — Function
load_simulation(simdir; strict = true) -> SimulationSpec

Read the MF6 simulation in directory simdir (mfsim.nam, TDIS, the GWF6 models and their packages, GWF6-GWF6 exchanges and IMS6 solutions) into a SimulationSpec, with MF6's checks and error messages (MF6InputError; design and differences in the header of src/input/simulation.jl).

Models other than GWF6, exchanges other than GWF6-GWF6, EMS6 and the out-of-scope packages (UNSUPPORTED_PACKAGES) are always an MF6UnsupportedError ("unsupported: SFR6 package 'SFR-1' in model 'GWF'"). With strict = true, so are options, values and features not (yet) implemented by the engine (SUPPORTED_OPTIONS, SUPPORTED_VALUES, SUPPORTED_FEATURES in src/input/supported.jl); strict = false reads all in-scope input (for inspection; the engine may then not run it).

Loading only reads files on the host; nothing is allocated on a device. Pass the result to run_simulation or initialize, or change it and write it back with write_simulation.

Example

spec = load_simulation("path/to/simulation")   # the directory with mfsim.nam
result = run_simulation(spec; outdir = "output")
source
ModflowGPU.MF6UnsupportedError — Type
MF6UnsupportedError(file, msg)

Input that ModflowGPU does not support (yet), thrown by load_simulation (and so by run_simulation and initialize) before anything runs. msg starts with "unsupported: " and names the package, option or feature; file is the input file (or ""). Nothing unsupported is silently ignored.

Example

julia> e = MF6UnsupportedError("model.npf", "unsupported: NPF option XT3D");

julia> sprint(showerror, e)
"MF6UnsupportedError: unsupported: NPF option XT3D (model.npf)"
source
ModflowGPU.MF6InputError — Type
ModflowGPU.MF6InputError(file, line, msg)

An error in an MF6 input file, thrown by load_simulation (and so by run_simulation and initialize) with MF6's message where MF6 has one. showerror prints file:line: msg (line = 0 when the error is not about a particular line).

Example

julia> sprint(showerror, ModflowGPU.MF6InputError("model.dis", 12, "NLAY must be > 0"))
"MF6InputError: model.dis:12: NLAY must be > 0"
