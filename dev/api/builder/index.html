Building models

The builder functions make a SimulationSpec from Julia arrays, with the checks MF6 applies to its input. Grid arrays have the shape (ncol, nrow, nlay) (MF6's memory order); most values may also be a scalar or one value per layer. The result can be run directly with run_simulation or initialize, or written as MF6 input files with write_simulation, which MF6 runs too.

build_dis builds DIS grids; DISV and DISU grids (a DisvSpec or DisuSpec, for example from a loaded simulation) are accepted by the other builders and by write_simulation. Several models are connected by GWF6-GWF6 exchanges (build_exchange, passed to build_simulation as exchanges), solved in one IMS solution. write_simulation also writes the OBS6, TS6 and TAS6 files of a loaded simulation (the series as read, with SFAC applied; a value linked to a series is written as the series name). Units are those of the model: lengths in its length units (length_units of build_dis), times in its time units (time_units of build_tdis).

julia> dis = build_dis(; delr = 100.0, delc = 100.0, top = 0.0, botm = fill(-10.0, 10, 5, 1));

julia> chd = build_boundary(:CHD, dis; periods = [1 => (; cells = [(1, 1, 1), (1, 5, 10)], values = [0.0, -2.0])]);

julia> gwf = build_model("flow"; dis, npf = build_npf(dis; k = 10.0), ic = build_ic(dis; strt = 0.0), boundaries = [chd]);

julia> sim = build_simulation(gwf; tdis = build_tdis(; perlen = 1.0))
SimulationSpec(1 model(s): FLOW; 1 period(s); 0 exchange(s))
ModflowGPU.SimulationSpec — Type
SimulationSpec

A whole simulation: simdir (the directory file names are relative to; "" for specs built in memory), the mfsim.nam options (continue_on_nonconvergence (CONTINUE), nocheck, memory_print_option, profile_option, maxerrors (0 = MF6 default), print_input), tdis, the GWF models (in mfsim.nam order), exchanges and solution_groups. Look up a model with model_spec(spec, name).

A plain host-side description in Float64, with no device data. It is made by load_simulation (from MF6 input files) or build_simulation (from Julia arrays), and taken by run_simulation, initialize and write_simulation. The specs of its parts (TdisSpec, GwfSpec, DisSpec, ...) are not part of the public API; read them, but build them with the builder functions.

Example

spec = load_simulation("path/to/simulation")
spec.models[1].name, spec.tdis.perlen

ModflowGPU.build_dis — Function
build_dis(; delr, delc, top, botm, idomain = nothing, xorigin = 0.0, yorigin = 0.0,
          angrot = 0.0, length_units = :undefined, nogrb = false, grb_file = "",
          file = "") -> DisSpec

A structured grid. botm is (ncol, nrow, nlay) (a matrix for one layer); delr is a scalar or a vector of ncol, delc a scalar or a vector of nrow, top a scalar or (ncol, nrow); idomain is nothing (all active), (ncol, nrow) (the same in every layer, as ModflowCoupling's land mask) or (ncol, nrow, nlay). The geometry is checked as MF6 does (check_dis_grid: positive thickness of active cells, at least one active cell); invalid input is an ArgumentError.

Lengths (delr, delc, top, botm, origins) are in the model's length units (length_units, e.g. :meters); angrot is in degrees. file is the file name the spec is written to by write_simulation (default <model>.dis).

Example

A grid of 10 columns, 5 rows and 2 layers of 100 m × 100 m cells:

julia> botm = cat(fill(-10.0, 10, 5), fill(-50.0, 10, 5); dims = 3);

julia> dis = build_dis(; delr = 100.0, delc = 100.0, top = 0.0, botm, length_units = :meters);

julia> (dis.ncol, dis.nrow, dis.nlay)
(10, 5, 2)

ModflowGPU.build_npf — Function
build_npf(dis; k, icelltype = 0, k22 = nothing, k33 = nothing, angle1 = nothing,
          angle2 = nothing, angle3 = nothing, wetdry = nothing, options...) -> NpfSpec

Node property flow on grid dis. Each array is a scalar, one value per layer, a vector by user node or a grid-shaped array ((ncol, nrow, nlay)); nothing means not given (MF6 then uses K22 = K33 = K and zero angles). K, K22 and K33 must be positive in active cells. options are the other NpfSpec fields (cell_averaging, save_flows, ...).

k, k22 and k33 are hydraulic conductivities (L/T, model units); icelltype 0 is a confined cell, other values a convertible cell (as MF6); angles are in degrees.

Example

julia> npf = build_npf(dis; k = [10.0, 1.0], k33 = 0.1, icelltype = [1, 0]);

julia> npf.k[[1, 51]]   # the first cell of each layer
2-element Vector{Float64}:
 10.0
  1.0

ModflowGPU.build_sto — Function
build_sto(dis; ss, iconvert = 0, sy = nothing, periods = (), options...) -> StoSpec

Storage on grid dis. periods are kper => :steady_state / kper => :transient pairs (MF6's PERIOD blocks; before the first one a model with STO is transient). SS and SY must not be negative in active cells; convertible cells need SY. options are the other StoSpec fields (storagecoefficient, ss_confined_only, save_flows, file).

ss is the specific storage (1/L; with storagecoefficient = true the storage coefficient, dimensionless), sy the specific yield (dimensionless).

Example

Steady state in the first stress period, transient from the second on:

julia> sto = build_sto(dis; ss = 1e-5, sy = 0.15, iconvert = 1,
                       periods = [1 => :steady_state, 2 => :transient]);

julia> sto.sy[1]
0.15

ModflowGPU.build_oc — Function
build_oc(; head_file = "", budget_file = "", budgetcsv_file = "",

Output control. periods are kper => records pairs, the records OcRecords or their text ("SAVE HEAD ALL", see oc_record); an empty list turns output off from that period on. head_file and budget_file are the names of the binary output files (none written when empty).

ModflowGPU.build_boundary — Function
build_boundary(kind, dis; periods, name = "", auxnames = String[], auxmultname = "",
               auxdepthname = "", boundnames = false, maxbound = 0, nseg = 1,
               surf_rate_specified = false, fixed_cell = false, print_input = false,
               print_flows = false, save_flows = false, file = "") -> BoundarySpec{kind}

A list stress package (kind one of BOUNDARY_KINDS) on grid dis. periods are kper => (; cells, values, aux, boundnames, layer) pairs, the records of each PERIOD block (they apply until the next block; an empty cells list removes all stresses):

  • cells: MF6 cellids (k, i, j), array indices CartesianIndex(j, i, k) (the (ncol, nrow, nlay) shape), CartesianIndex(j, i) with layer (one integer or one per cell; default 1), or user node numbers. Cells must be active.
  • values: (nrecords, ncolumns), the double columns of the DFN record in order (CHD head; WEL q; RCH recharge; GHB bhead cond; RIV stage cond rbot; DRN elev cond; EVT surface rate depth, then pxdp, petm (nseg - 1 each) and petm0 with surf_rate_specified); a vector when there is one column.
  • aux: (nrecords, length(auxnames)); boundnames: one name per record (with boundnames = true).

maxbound = 0 uses the largest number of records of a period. An empty name gets MF6's default ("WEL-1", ...) in build_model.

Values are in the model's units: heads, stages and elevations in L, conductances in L²/T, well rates in L³/T (negative for pumping), recharge and evapotranspiration rates in L/T.

Example

Two constant-head cells and a river cell in stress period 1, the river stage raised in period 2:

julia> chd = build_boundary(:CHD, dis; periods = [1 => (; cells = [(1, 1, 1), (1, 5, 10)], values = [0.0, -2.0])]);

julia> riv = build_boundary(:RIV, dis; name = "river",
                            periods = [1 => (; cells = [(1, 3, 5)], values = [-1.0 500.0 -3.0]),
                                       2 => (; cells = [(1, 3, 5)], values = [-0.5 500.0 -3.0])])
BoundarySpec{:RIV}("RIVER", list, periods [1, 2])

ModflowGPU.build_array_boundary — Function
build_array_boundary(kind, dis; periods, name = "", auxnames = String[],
                     auxmultname = "", fixed_cell = false, print_input = false,
                     print_flows = false, save_flows = false, file = "")
    -> BoundarySpec{kind}

A READASARRAYS stress package (RCHA: kind = :RCH; EVTA: kind = :EVT) on a DIS or DISV grid. periods are kper => (; name = array, ...) pairs: the arrays given in that PERIOD block (recharge, irch; surface, rate, depth, ievt; auxiliary variables by name), each a scalar, (ncol, nrow) or a vector of ncpl. Arrays not given keep their previous values (zero, layer 1 at first), as in MF6. Rates are in L/T in the model's units.

Example

Recharge on the top layer, a uniform rate in period 1 and a map in period 2:

julia> rcha = build_array_boundary(:RCH, dis;
                                   periods = [1 => (; recharge = 1e-3), 2 => (; recharge = fill(2e-3, 10, 5))])
BoundarySpec{:RCH}("", arrays, periods [1, 2])

ModflowGPU.build_model — Function
build_model(name; dis, npf, ic, sto = nothing, oc = nothing, boundaries = [],
            list_file = "", print_input = false, print_flows = false,
            save_flows = false, newton = false, newton_under_relaxation = false,
            file = "") -> GwfSpec

A GWF model from package specs (build_dis, build_npf, build_ic, build_sto, build_oc, build_boundary, build_array_boundary). boundaries are given in name-file order; the spec holds them in MF6's order (WEL, DRN, RIV, GHB, RCH, EVT, CHD, then this order). Unnamed stress packages get MF6's default names ("CHD-1", ...). Files without a name get <name>.<ext> (lower case; <name>.<package name> for stress packages), the names write_simulation uses. Model names have at most 16 characters (MF6).

Example

julia> chd = build_boundary(:CHD, dis; periods = [1 => (; cells = [(1, 1, 1), (1, 5, 10)], values = [0.0, -2.0])]);

julia> wel = build_boundary(:WEL, dis; periods = [1 => (; cells = [(1, 3, 5)], values = [-100.0])]);

julia> gwf = build_model("flow"; dis, npf = build_npf(dis; k = 10.0), ic = build_ic(dis; strt = 0.0),
                         boundaries = [chd, wel])
GwfSpec("FLOW", DisSpec, boundaries: WEL-1, CHD-1)

ModflowGPU.build_tdis — Function
build_tdis(; perlen, nstp = 1, tsmult = 1.0, time_units = :undefined,
           start_date_time = "", file = "") -> TdisSpec

Time discretization: perlen (the length of each stress period, in time_units, e.g. :days); nstp (time steps per period) and tsmult (the ratio of successive step lengths) a scalar (every period) or one value per period. Checked as MF6's check_tdis_timing.

Example

A steady-state period of one day, then ten periods of 30 days with 5 steps each:

julia> tdis = build_tdis(; perlen = [1.0; fill(30.0, 10)], nstp = [1; fill(5, 10)], time_units = :days);

julia> sum(tdis.nstp)
51

ModflowGPU.build_ims — Function
build_ims(; complexity = nothing, models = String[], file = "", settings...) -> ImsSpec

An IMS solution: MF6's defaults of complexity (:simple when not given) with the ImsSpec fields in settings (outer_dvclose = 1e-6, linear_acceleration = :bicgstab, ...). given lists the keywords passed (COMPLEXITY included when given), in the order write_simulation writes them. models is filled in by build_simulation when empty. Closures are in the model's units (head change in L for the dvclose settings).

The linear-solver preconditioner of IMS (ILU0, MILU0, ILUT) is not used: ModflowGPU replaces it by its own (the preconditioner keyword of run_simulation).

Example

julia> ims = build_ims(; complexity = :moderate, outer_dvclose = 1e-4, linear_acceleration = :bicgstab);

julia> ims.given
3-element Vector{String}:
 "COMPLEXITY"
 "OUTER_DVCLOSE"
 "LINEAR_ACCELERATION"
source
ModflowGPU.build_exchange — Function
build_exchange(m1, m2; cells1, cells2, ihc, cl1, cl2, hwva, aux = (;), boundnames = nothing,
               print_input = false, print_flows = false, save_flows = false,
               cell_averaging = :harmonic, variablecv = false, dewatered = false,
               newton = false, xt3d = false, file = "") -> ExchangeSpec

A GWF6-GWF6 exchange (T6.9) between the models m1 and m2 (build_model; the same model for a periodic exchange): connection i joins cell cells1[i] of m1 and cells2[i] of m2 (MF6 cellids, CartesianIndexes or user nodes, as for build_boundary), with ihc (0 vertical, 1 horizontal, 2 vertically staggered), the distances cl1, cl2 from each cell centre to the shared face and hwva (face width or, vertical, area); scalars apply to every connection. aux gives auxiliary variables by name (e.g. (; ANGLDEGX = ..., CDIST = ...), which XT3D and SAVESPECIFICDISCHARGE need), boundnames a name per connection. Both cells must be active. The file is <model1>_<model2>.gwfgwf unless file is given. Pass the exchanges to build_simulation.

source
ModflowGPU.build_simulation — Function
build_simulation(models; tdis, ims = build_ims(), mxiter = 1, simdir = "",
                 continue_on_nonconvergence = false, nocheck = false,
                 memory_print_option = "", profile_option = "", maxerrors = 0,
                 print_input = false, exchanges = ExchangeSpec[]) -> SimulationSpec

A simulation of one or more GWF models (build_model) solved by one IMS solution in one solution group, connected by the GWF6-GWF6 exchanges (build_exchange, T6.9). The IMS solution gets the model names when its models is empty; TDIS and IMS files without a name get <first model>.tdis / .ims. Period data must not refer to stress periods after the last one.

The result can be run directly (run_simulation, with outdir for the output files) or written as MF6 input (write_simulation).

Example

A one-layer model with two constant heads and a well, in steady state:

julia> dis = build_dis(; delr = 100.0, delc = 100.0, top = 0.0, botm = fill(-10.0, 10, 5, 1));

julia> chd = build_boundary(:CHD, dis; periods = [1 => (; cells = [(1, 1, 1), (1, 5, 10)], values = [0.0, -2.0])]);

julia> wel = build_boundary(:WEL, dis; periods = [1 => (; cells = [(1, 3, 5)], values = [-100.0])]);

julia> oc = build_oc(; head_file = "flow.hds", budget_file = "flow.cbc",
                     periods = [1 => ["SAVE HEAD ALL", "SAVE BUDGET ALL"]]);

julia> gwf = build_model("flow"; dis, npf = build_npf(dis; k = 10.0), ic = build_ic(dis; strt = 0.0),
                         oc, boundaries = [chd, wel]);

julia> sim = build_simulation(gwf; tdis = build_tdis(; perlen = 1.0))
SimulationSpec(1 model(s): FLOW; 1 period(s); 0 exchange(s))

ModflowGPU.write_simulation — Function
write_simulation(dir, spec::SimulationSpec) -> dir

Write spec as MF6 input files into dir (created when missing): mfsim.nam and every file under the name in its spec (file fields, PackageEntrys), as build_model and build_simulation set them. load_simulation(dir) gives spec back (spec_identical(spec, load_simulation(dir); ignore = (:simdir,))), and mf6 runs it.

Supported: GWF models on DIS, DISV and DISU grids with NPF, IC, STO, OC, OBS6, HFB6 (T6.11), TVK6 and TVS6 (T6.12, with their TS6 files), GNC6 (T6.13, also on exchanges), the stress packages of BOUNDARY_KINDS (lists, and READASARRAYS on DIS and DISV), TDIS, IMS and GWF6-GWF6 exchanges (with their OBS6), and the TS6 and TAS6 files of the stress packages (T6.10: the series as loaded, SFAC applied; values linked to a series written as its name). ATS input is an ArgumentError. Ported from ModflowCoupling's write_simulation (src/mf6_writer.jl there).

Example

julia> dir = write_simulation(mktempdir(), sim);

julia> readdir(dir)
8-element Vector{String}:
 "flow.chd-1"
 "flow.dis"
 "flow.ic"
 "flow.ims"
 "flow.nam"
 "flow.npf"
 "flow.tdis"
 "mfsim.nam"

julia> load_simulation(dir)
SimulationSpec(1 model(s): FLOW; 1 period(s); 0 exchange(s))
