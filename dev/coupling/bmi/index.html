BMI

ModflowGPU implements the Basic Model Interface (BMI) of BasicModelInterface.jl (version 0.1) for its Simulation type, so that a BMI host (a coupler that drives models through BMI calls only) can run it like any other BMI model. The methods are built on the stepping API, and follow libmf6's BMI: variable names are the libmf6 addresses of the stepping API, and the model has one grid.

The BMI functions belong to BasicModelInterface, not to ModflowGPU. Add the package to your environment (import Pkg; Pkg.add("BasicModelInterface")) and call them with its module name:

import BasicModelInterface as BMI
using ModflowGPU
sim = BMI.initialize(Simulation, "path/to/simulation"; backend = select_backend("auto"))

Variables

Variable names are the addresses of the stepping API, e.g. "GWF/X" or "GWF/RIV-1/BOUND".

Values are in the forms of the stepping API: Float64 with absolute heads, BOUND before the MULTIPLIER auxiliary variable, Int32 for counts and node numbers. The host mirror returned by get_value_ptr is a copy of the engine data, synchronised at the stepping calls; see Host mirrors and device arrays. The device arrays are not reachable through BMI.

Setting boundary values through BMI

BMI.update runs a whole time step, so a BMI host sets values before the step starts. At the first step of a stress period, the period data of a package (a PERIOD block in its input) replace the values set before, as in MF6. Values set for a package without a PERIOD block for the coming period are kept. To set boundary values in every period, call the stepping API directly and set them after prepare_time_step.

Grid

Every model variable is on grid 1, the model grid. Its size is the number of cells of the grid, user nodes, including cells with IDOMAIN ≤ 0. Node variables such as X have one value per model node (cells with IDOMAIN > 0) instead; <model>/DIS/NODEUSER gives the user node of each model node. Without IDOMAIN the two are the same.

The coordinates are those of the model (XORIGIN, YORIGIN); the rotation ANGROT is not applied. Cell elevations are the <model>/DIS/TOP and <model>/DIS/BOT variables, and the cell areas <model>/DIS/AREA.

Not implemented

These BMI functions have no method for Simulation (calling them throws a MethodError): get_grid_origin, get_grid_spacing, get_grid_z, get_grid_edge_count, get_grid_face_count, get_grid_edge_nodes, get_grid_face_edges, get_grid_face_nodes and get_grid_nodes_per_face. Use get_grid_x and get_grid_y for a DIS grid, and the DIS variables for the elevations.

A BMI loop

A steady-state model of 10 × 5 cells with constant heads on the west and east edges and a well in the middle, written as MF6 input and run through BMI. The well pumps the rate of its input in the first period, and a rate set through BMI in the next two (its input has no data for periods 2 and 3, so the set values are kept):

julia> import BasicModelInterface as BMI

julia> using ModflowGPU

julia> dis = build_dis(; delr = 100.0, delc = 100.0, top = 0.0, botm = fill(-20.0, 10, 5, 1));

julia> chd = build_boundary(:CHD, dis;
           periods = [1 => (; cells = [(1, i, j) for i in 1:5 for j in (1, 10)], values = zeros(10))]);

julia> wel = build_boundary(:WEL, dis; periods = [1 => (; cells = [(1, 3, 5)], values = [-100.0])]);

julia> gwf = build_model("flow"; dis, npf = build_npf(dis; k = 10.0), ic = build_ic(dis; strt = 0.0),
           boundaries = [chd, wel]);

julia> spec = build_simulation(gwf; tdis = build_tdis(; perlen = fill(10.0, 3), time_units = :days));

julia> simdir = write_simulation(joinpath(mktempdir(), "flow"), spec);

julia> sim = BMI.initialize(Simulation, simdir; precision = :double);
┌ Info: IMS preconditioner ILU0 is replaced by mc_ilu0 (multicolour ILU0: red–black on DIS grids, greedy colouring on DISV and DISU; the default, see the `preconditioner` option)

julia> BMI.get_time_units(sim), BMI.get_end_time(sim)
