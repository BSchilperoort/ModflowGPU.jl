BMI

ModflowGPU has two Basic Model Interfaces (BMI, the functions of BasicModelInterface.jl version 0.1), chosen by the model type:

SimulationMF6Model
Followsthe BMI specificationlibmf6, the BMI of MODFLOW 6, as ModflowInterface.jl wraps it
Use it fora BMI host that drives models through BMI calls onlycode written for libmf6 through ModflowInterface.jl, which runs unchanged after swapping ModflowModel for MF6Model
StartBMI.initialize(Simulation, config_file) (configuration file)m = MF6Model(path; backend, precision, ...), then BMI.initialize(m)
Gridsreal-world coordinates, units, a grid for every variablelibmf6's: one grid per model, DIS x and y are indices
Functionsall 41 of the specificationthe ones libmf6 has, and the XMI calls of ModflowInterface.jl

Both are built on the stepping API and use its variable names (libmf6 addresses such as "GWF/X"). The sections below up to A BMI loop describe the BMI of Simulation; libmf6's BMI: MF6Model describes the other.

Simulation implements all 41 functions of the specification; the conformance table lists what each one does and the deviations that remain.

The BMI functions belong to BasicModelInterface, not to ModflowGPU. Add the package to your environment (import Pkg; Pkg.add("BasicModelInterface")) and call them with its module name:

import BasicModelInterface as BMI
using ModflowGPU
sim = BMI.initialize(Simulation, "path/to/run.toml")

Configuration file

As the BMI specification asks, BMI.initialize(Simulation, config_file) takes no other arguments: the settings come from a configuration file in TOML format. Its keys are the keywords of initialize:

simulation = "model"          # the simulation folder or its mfsim.nam (required)
backend = "rocm"              # a name for select_backend: "cpu" (default), "auto", "rocm", "cuda", ...
precision = "single"          # "auto" (default), "double", "mixed" or "single"
preconditioner = "auto"       # "auto" (default), "jacobi", "chebyshev", "mc_sgs", "mc_ilu0" or "amg"
outdir = "output"             # folder for the output files (default: the simulation folder)
write_output = true           # false writes no output files but the OBS6 observations

[closures]                    # overrides of the IMS closures (optional)
outer_dvclose = 1.0e-4
inner_maximum = 200

[precond_options]             # options of the preconditioner (optional)
relax = 0.97
  • Only simulation is required; the other keys take the defaults of initialize. Unknown keys, closures that IMS does not have, and values of the wrong type are errors.
  • simulation and outdir are relative to the folder of the configuration file (or absolute).
  • closures takes outer_dvclose, outer_maximum, inner_dvclose, inner_rclose and inner_maximum. Strings in precond_options become symbols (for example the AMG option smoother = "chebyshev").
  • A GPU backend needs its package loaded before BMI.initialize is called (using AMDGPU, using CUDA, ...; see GPUs and precision).
  • config_file can also be the simulation folder or its mfsim.nam, which runs with all defaults (on the CPU, with output files in the simulation folder).

To pass settings as keywords instead, call initialize of the stepping API: it returns the same Simulation, which the BMI functions then accept. BMI.initialize(Simulation, config_file; precision = :double) is an error.

Control and time

BMI.update(sim)one time step (ModflowGPU.update); throws a ConvergenceError when the step does not converge and the simulation has no CONTINUE option

Times start at 0 and are in the time units of the model. get_current_time is the time at the end of the last completed time step (0 before the first update).

ModflowGPU does not split time steps, so update_until(sim, time) accepts only a time at the end of a time step (within a relative tolerance of 10⁻¹⁰ of the end time) and throws an ArgumentError for any other time, for a time before the current time, and for a time after the end of the simulation. time equal to the current time does nothing. To couple at times that are not step ends, give the model matching time steps in TDIS.

Values are in the forms of the stepping API: Float64 with absolute heads (also in precision = :single runs), BOUND before the MULTIPLIER auxiliary variable, Int32 for counts and node numbers. Arrays are flattened in Julia's (column-major) order, so a BOUND of (ncol, maxbound) lists the values of record 1, then of record 2, and so on. The host mirror returned by get_value_ptr is a copy of the engine data, synchronised at the stepping calls; see Host mirrors and device arrays. The device arrays are not reachable through BMI.

Setting boundary values through BMI

BMI.update runs a whole time step, so a BMI host sets values before the step starts. At the first step of a stress period, the period data of a package (a PERIOD block in its input) replace the values set before, as in MF6. Values set for a package without a PERIOD block for the coming period are kept. To set boundary values in every period, call the stepping API directly and set them after prepare_time_step.

Units

BMI.get_var_units gives the units in UDUNITS syntax, from the DIS LENGTH_UNITS and the TDIS TIME_UNITS of the model, as the Units column of the address table:

Address tableLENGTH_UNITS meters, TIME_UNITS daysNot given in the input
L (heads, elevations)"m""L"
L² (areas)"m2""L2"
L³/T (flows: SIMVALS)"m3 d-1""L3 T-1"
T (TDIS/DELT, TOTIM, PERTIM)"d""T"
- (counts, node numbers, IBOUND)"1""1"

The length units are "m", "ft" or "cm", the time units "s", "min", "h", "d" or "yr". MODFLOW itself does not use units, so a model may leave them out; the BMI then gives the placeholders "L" and "T", which are not UDUNITS units. BOUND has the units of its column for the packages with one column (CHD: L, WEL: L³/T, RCH and RCHA: L/T), and "none" for the others, whose columns have different units (see the BOUND columns).

Ask BMI.get_var_grid(sim, "<model>/X") rather than counting. libmf6's BMI (MF6Model) gives each model one grid, its number in the solution, as libmf6 does.

A DIS grid with ANGROT ≠ 0 or more than one layer is "structured_quadrilateral", with the coordinates of every cell (get_grid_size values, in user-node order: layer by layer, row by row from the north).

Deviations from the specification

  • Time steps are not split: update_until accepts only times at the end of a time step, and never runs backwards.
  • get_value_ptr is a mirror: the model's data are on the device, so the returned vector is a host copy that the time-step calls keep up to date; writes into it reach the model at the next time step. See Host mirrors and device arrays.
  • Units placeholders: without LENGTH_UNITS or TIME_UNITS in the input, the units contain L or T, which UDUNITS does not know. BOUND of RIV, GHB, DRN and EVT has "none".
  • 1-based indices: indices passed to *_at_indices and returned by the unstructured grid functions start at 1 (Julia), where the CSDMS examples (in C and Python) start at 0.
  • Grids of layered unstructured models are given in plan view (rank 2, no get_grid_z); the cell elevations are the variables <model>/DIS/TOP and BOT.
  • Values in Float64: a precision = :single run still exchanges Float64 values (the host mirrors), so get_var_type does not show the precision of the run.
Changes from earlier versions

Before the BMI was checked against the specification, BMI.initialize took the settings as keywords; put them in a configuration file now. get_grid_x and get_grid_y of a DIS grid gave the ncol + 1 and nrow + 1 cell edges without ANGROT; they now give the cell centres in real-world coordinates. Grids 0 and 2 and the package grids are new (the scalar and package variables had no grid), DISV and DISU grids give their vertices and faces, the units are UDUNITS strings ("m3 d-1" for "L3/T"), get_time_units gives "none" instead of "undefined", get_value_ptr returns a flat Vector for BOUND, and update_until throws for times that are not step ends instead of running past them. These changes are to the BMI of Simulation; the libmf6 behaviour (edge indices, a matrix BOUND, one grid per model) is that of MF6Model.

libmf6's BMI: MF6Model

MF6Model gives the results of libmf6, the BMI of MODFLOW 6 (srcbmi/ of MODFLOW 6.8.2), and is used as ModflowModel of ModflowInterface.jl: a script written for libmf6 runs on ModflowGPU after changing the using line and the model type. Engine settings, which libmf6 does not have, are keywords of the constructor (those of initialize); without them the model runs on the CPU in the default precision.

import BasicModelInterface as BMI
using ModflowGPU                   # was: using ModflowInterface
const MF = ModflowGPU              # was: const MF = ModflowInterface

m = MF6Model("path/to/simulation"; backend = select_backend("auto"))   # was: ModflowModel(...)
BMI.initialize(m)
head = BMI.get_value_ptr(m, "GWF/X")
maxiter = BMI.get_value_ptr(m, "SLN_1/MXITER")[]
while BMI.get_current_time(m) < BMI.get_end_time(m)
    MF.prepare_time_step(m, 0.0)
    rate = BMI.get_value_ptr(m, "GWF/WEL-1/BOUND")   # (ncolbnd, maxbound)
    rate[1, :] .= -100.0
    MF.prepare_solve(m, 1)
    for _ in 1:maxiter
        MF.solve(m, 1) && break
    end
    MF.finalize_solve(m, 1)
    MF.finalize_time_step(m)
end
BMI.finalize(m)

Differences from libmf6

The test group bmi runs one script written for ModflowInterface.jl on MF6Model and, through ModflowInterface.jl, on libmf6 6.3.0 (the Modflow6_jll that ModflowInterface.jl installs) and 6.8.2, and compares every result. These differ:

  • Failures are errors. Where libmf6 returns a failure status (which ModflowInterface.jl ignores, returning 0, "" or an unchanged buffer), MF6Model throws an ArgumentError and keeps its message for get_last_bmi_error: an unknown address, a grid id other than 1, and the grid functions libmf6 has only for some grid types (get_grid_rank and get_grid_shape for DISV and DISU; get_grid_size, get_grid_node_count and the face functions for DIS and DISV).
  • get_grid_y of DIS gives nrow:-1:0: a deliberate fix of a libmf6 bug. libmf6 6.8.2 gives ncol:-1:0, because mf6bmiGrid.f90 takes the last entry of the grid shape (ncol) instead of nrow: y_size = grid_shape_ptr(size(grid_shape_ptr - 1)) + 1 (the - 1 is inside size). It so writes past a buffer of nrow + 1 values (sized from get_grid_shape) when ncol > nrow.
  • Destination buffers of the grid functions (get_grid_x, get_grid_y, get_grid_shape, get_grid_nodes_per_face, get_grid_face_nodes) are checked: a buffer shorter than the values throws an ArgumentError with the length needed, and nothing is written past its end (libmf6 does not check).
  • get_time_step gives the step length. ModflowInterface.jl's get_time_step calls libmf6's get_end_time and gives the end time (and its get_start_time calls get_current_time, which is 0 only before the first step).
  • Before the first time step, TDIS/DELT and get_time_step are the length of the first step (libmf6: 0), XOLD is the starting head and SIMVALS are 0 (libmf6: not initialised).
  • NODEUSER and NODEREDUCED of a model without excluded cells are, as in libmf6, arrays of length 1; their value is 0 (libmf6: arbitrary).
  • Addresses: only those of var_addresses exist (libmf6 lists every array of its memory manager); <model>/HREF exists only in ModflowGPU.
  • BOUND holds the package data as libmf6 up to 6.4 does (before the AUXMULTNAME multiplier). libmf6 6.8 keeps them in separate arrays (WEL/Q, CHD/HEAD, RIV/STAGE, ...) and leaves BOUND at 0, so writing BOUND has no effect there; see Differences from MODFLOW 6.
  • get_value_ptr is a host mirror of the device data, synchronised at the stepping calls, not the model's own memory; see Host mirrors and device arrays.
  • get_grid_face_nodes of DISU with excluded cells works; libmf6 corrupts its memory there (it sizes a buffer by the face count, the number of model nodes, and writes the nodes per face of every cell).
  • The handle is finalised when garbage-collected, as ModflowInterface.jl's ModflowModel. Because the garbage collector does not allow I/O or device synchronisation, the finalizer finalises the simulation in a new task: output files are closed and GPU memory is freed some time after the collection (not at all if Julia exits first). Call BMI.finalize(m) to release them at a known point; a second call does nothing. Several MF6Models can be active at a time; libmf6 allows one per process.

Functions libmf6 does not have

update_until, get_var_units, get_var_location, get_time_units, get_value_at_indices, set_value_at_indices, get_grid_z, get_grid_spacing, get_grid_origin, get_grid_edge_count, get_grid_edge_nodes and get_grid_face_edges throw an ArgumentError for an MF6Model that points to the BMI of Simulation, which has them all (m.simulation, or BMI.initialize(Simulation, config_file)).
