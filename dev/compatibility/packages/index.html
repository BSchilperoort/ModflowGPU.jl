Supported packages

ModflowGPU runs MODFLOW 6 groundwater flow (GWF) models: one GWF model with one IMS solution. This page lists what it reads and runs. The tables in the first three sections are generated from the checks in the code when this manual is built, so they are always current.

Reading is strict: anything outside these tables stops the run with an MF6UnsupportedError that names the file, the package and the option, before anything runs. No option is silently ignored (see Getting started). A few options are accepted but behave differently from MODFLOW 6; they are listed on Differences from MODFLOW 6.

Packages and options

Each row is one block of one input file, with the options ModflowGPU accepts in it. Where an option selects a method, only the values in brackets are accepted. Grid data, initial conditions, package data and stress-period data (GRIDDATA, PACKAGEDATA, PERIOD and similar blocks) are read as MODFLOW 6 reads them, including OPEN/CLOSE files, binary arrays and lists, LAYERED arrays, CONSTANT and FACTOR.

Notes:

  • TS6, TAS6 and OBS6 are FILEIN options of the stress packages. Time series are supported (see below). An observation file must exist, but it is not read and no observation output is written yet.
  • PRINT_INPUT, PRINT_FLOWS, MEMORY_PRINT_OPTION and PROFILE_OPTION are accepted and have no effect on the output (see the listing file on Differences from MODFLOW 6).
  • SAVE_SPECIFIC_DISCHARGE is accepted, but the DATA-SPDIS record is not written to the budget file.
  • IMS: the ILU preconditioner options (PRECONDITIONER_LEVELS, PRECONDITIONER_DROP_TOLERANCE, RELAXATION_FACTOR) are accepted, but ModflowGPU uses its own preconditioner (see Differences from MODFLOW 6). The backtracking options (BACKTRACKING_NUMBER, _TOLERANCE, _REDUCTION_FACTOR, _RESIDUAL_LIMIT, and the backtracking that COMPLEXITY COMPLEX turns on) are applied as in MODFLOW 6.
  • In OC, HEAD and BUDGET stand for HEAD FILEOUT, BUDGET FILEOUT and HEAD PRINT_FORMAT (accepted, not applied). The PERIOD blocks accept SAVE and PRINT of HEAD and BUDGET with ALL, FIRST, LAST, FREQUENCY and STEPS.
  • A model can have several packages of one type (for example three RCH packages).

Model features

Besides options, the input is checked for features that change how the model is solved. These are supported:

FeatureSupported
Convertible cells (NPF ICELLTYPE ≠ 0), with wetting and drying (REWET, WETDRY)yes
Convertible storage (STO ICONVERT ≠ 0, specific yield) in transient periodsyes
Unstructured grids (DISU6)yes
Vertex grids (DISV6)yes
Newton–Raphson formulation (NEWTON and NEWTON UNDER_RELAXATION in the model name file)yes
Time series (TS6 files, list values given as time-series names) and time-array series (TAS6 files for RCH and EVT with READASARRAYS)yes

Both the standard formulation of convertible cells and wetting and drying (REWET with WETDRY, WETFCT, IWETIT, IHDWET) are supported, as are THICKSTRT, VARIABLECV (with DEWATERED) and PERCHED.

The Newton–Raphson formulation (NEWTON in the options of the model name file) is supported as in MODFLOW 6:

  • the saturation of convertible cells is the quadratic smoothing of MODFLOW 6 (SATOMEGA 1e-6), horizontal conductances use the saturation of the upstream cell, cells do not dry (a cell whose head falls below its bottom keeps that head and has no outflow), and the matrix gets the Newton terms of NPF, STO (convertible storage), WEL with AUTO_FLOW_REDUCE and DRN with AUXDEPTHNAME (which then scales the conductance with MODFLOW 6's cubic function);
  • NPF HIGHEST_CELL_SATURATION is supported; PERCHED, VARIABLECV and REWET are input errors with NEWTON, as in MODFLOW 6;
  • NEWTON UNDER_RELAXATION limits heads that fall below the bottom of the lowest convertible cell;
  • in steady-state stress periods the pseudo-transient continuation of IMS is applied (turned off with the IMS option NO_PTC ALL, or NO_PTC FIRST for the first period);
  • the matrix is not symmetric: IMS must use LINEAR_ACCELERATION BICGSTAB (the default of COMPLEXITY MODERATE and COMPLEX); CG is an input error, as in MODFLOW 6.

Backtracking with Newton–Raphson works on the system without the Newton terms, as in MODFLOW 6. How the results compare with MODFLOW 6 is on Differences from MODFLOW 6 and Comparing results.

Out of scope, and why

ModflowGPU is built to run large groundwater flow models on a GPU, coupled to land-surface and hydrology models that compute the surface water themselves. That decides what is in scope. These parts of MODFLOW 6 will not be supported:

FeatureWhy it is out of scope
SFR, LAK, MAW, UZF (streams, lakes, multi-aquifer wells, unsaturated zone)Their own nonlinear equations and sequential routing (streams downstream, lake stages, well heads) do not map well onto a GPU. In the coupled models ModflowGPU is made for, the hydrology model handles rivers, lakes and the unsaturated zone, and exchanges water with ModflowGPU through RIV, DRN, RCH and EVT.
MVR (water mover)Moves water between the packages above.
CSUB (compaction and subsidence)A separate physics package, not needed for regional and global flow.
BUY, VSC (density and viscosity)Only meaningful together with a transport model.
GWT, GWE, PRT (transport, energy, particle tracking)ModflowGPU solves groundwater flow only.
API packageThe stepping API and BMI of ModflowGPU give access to the model from Julia instead.
PETSc and parallel input (HPC6)ModflowGPU runs on one GPU with its own linear solver.
